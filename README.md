## 一、它解决什么

一个课题组里最贵的东西不是论文，是**「哪些路走不通」的集体记忆**。它通常以三种形式存在：
散在群聊里的截图、躺在某台机器上的日志、以及某个人脑子里的印象。三个月后，前两种找不到了，
第三种失真了，新来的学生于是从头再试一遍。

现有工具补不上这个缺口：飞书把一切建模成**文档**，GitHub 把一切建模成**代码**，
而科研的本质是一条可被验证的链条——`假设 → 代码版本 → 数据版本 → 实验结果 → 论文里的数字 → 结论`。
它们能存这条链上的每一份文件，**却不知道这条链的存在**。

## 二、三个入口

| 角色 | 时刻 | 他想要什么 | 入口 |
| --- | --- | --- | --- |
| 研究生（本人） | 一次尝试又卡住了 | 这条路以前有没有人走过？卡在哪？ | LearnBuddy 专家 |
| 新人 | 刚接手一个方向 | 这个方向的历史、已踩过的坑、还有哪些空白 | 网页 · 经验库 / 失败地图 / 可重试方向 |
| 导师 | 学生汇报说试过了 | 试过几次、结论是否被验证、证据是否充分 | 网页 · 立项检查 / 档案详情 |

**AI 能力全部在专家里，网页里没有一行模型调用。** 网页只做确定性的事：召回、视图、持久化。

```
    ├── src/rra/              Python 侧：契约 / 库 / 召回 / 技能 / 评测 / 种子 / 导出
    ├── prompts/              六份技能提示词（判定规则的唯一真源，参与盲测冻结）
    ├── expert/               专家包镜像（含 6 技能 + 确定性 CLI，可直接安装）
    ├── web/                  静态网页（零构建、零依赖、纯相对路径）
    ├── tests/                Python 测试（268 条）
    ├── tools/                命令行入口（不含业务逻辑）
    ├── reports/              评测结果、冻结记录、迭代留痕（必须入库）
    └── docs/                 交接说明、架构、交付形态、字段规范、网页视觉规格
```

## 四、快速开始

```bash
# 1) 跑一遍全部验证（Python 268 条 + 两端契约一致性 + 路由 / 排序 / 规则一致性 / 写失败原子性）
<python> 实现代码/run_tests.py

# 2) 本地看网页（必须走 http；file:// 下 ES module 会被 CORS 拦）
cd 实现代码/web && <python> -m http.server 8123
# 打开 http://127.0.0.1:8123/index.html
# 深链示例：#/resurrection、#/map、#/detail/R-003、#/library?q=显存&sort=confidence
```

`<python>` 指任意 Python 3.11+；除标准库外**无运行时依赖**。

## 七、AI 使用声明

本项目在开发过程中使用腾讯 **LearnBuddy** 作为学习与辅助工具（专家数字分身咨询、Skills 方法论、
长期记忆陪跑），完整对话记录按功能模块留档在 `实现代码/docs/learnbuddy/`。

作品自身对 AI 的使用是**结构性的**：语义判断全部由 LearnBuddy 专家完成，
确定性逻辑（契约校验、召回、去重、评测判据）全部由可测的普通代码完成，
网页侧不含任何模型调用。**所有 AI 生成的代码与结论均经团队成员理解、修改与验证后合入；
核心设计（选题、数据模型、架构取舍、评测口径）由团队自主完成。**

## 八、三条边界（我们在 PPT 与演示里主动说）

1. 库内数据为**模拟数据**（`provenance.source = 模拟`，界面上显式标注），原型不实现访问控制；
2. 专家与网页之间目前是**手动导入**传递，平台侧数据通路待实测确认；
3. 网页内的相似度计算定位为**检索召回**，语义判定由专家完成。
