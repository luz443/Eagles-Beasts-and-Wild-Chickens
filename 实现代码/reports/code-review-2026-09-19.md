## 二、修复清单（按严重度）

### 致命
1. **反驳功能会让整库永久存不下去**（`web/js/refute.js`）
   原实现生成的纠错档案 `boundary` 为空串，而契约要求该字段非空 → `save()` 必然抛错；
   更糟的是它先 `push` 进内存再 `save`，抛错后脏记录留在内存里，**此后任何保存都会失败**（需重启页面）。
   修：纠错档案补齐合法字段（boundary 填"仅针对某条判断"，引用片段从归因/观察/阻塞点逐级回退且强制 ≥4 字符），
   来源标注由「模拟」改为**「真实」**（人工纠错是真实输入），并改为"先整体校验、通过后才替换内存"。
2. **导入失败会污染内存，而界面还告诉用户"内存未受影响"**（`web/js/store.js` + `main.js`）
   原实现边循环 push 边 save。修：先算出合并结果 → 整库校验 → 通过才替换 `this.library`，失败即回滚。
   界面那句不实提示已删掉（现在这句话是真的了）。
3. **校验器会被畸形输入打崩**（`validator.py` / `contracts.js`）
   `records: [null]` 会让两边直接抛 TypeError/AttributeError，而不是报违规。
   修：元素类型守卫，改报 `records[0]：元素不是对象`。

### 高
4. **契约三处口径不一致**（schema ↔ Python ↔ 浏览器）
   - 编号正则：schema 是 `{3}`、两端是 `{3,}` → 统一为 `{3,}`（`R-1234` 这类不再出现"一边过一边拒"）；
   - **`additionalProperties: false` 声明了却没人执行** → 两端都真的执行未知字段检查；
   - 必填字段不查类型 → 非字符串（如 `"attempt": 42`）曾能通过，随后让视图 `.slice` 崩溃；
   - 浏览器侧缺 `evidence_refs` 指向存在性校验 → 补齐，与 Python 对齐；
   - schema 补 `minLength`（boundary / attribution.text / provenance.author / date），两端改为按**原串**长度判引用片段（原先是"schema 按原串、校验器按 trim"）。
5. **父对象缺失时两端级联报错不同**（`contracts.js`）
   缺 `attribution` 时 JS 还会报出 `attribution.type`/`attribution.text`，Python 不会。
   修：父对象缺失或类型不对时**不下探**子字段（这正是"两端一致性测试"上线后抓到的第一个真问题）。
6. **去重指纹与文档口径不符**（`dedup.py` / `store.js`）
   文档写"尝试 + 阻塞点 + 关键条件"，实现里**没有条件** → 两条只有序列长度不同的记录会被判为重复而静默丢弃。
   修：指纹纳入 links 里的条件（same/diff），且条件与关联产物**排序后**参与（否则同样的档案只因条目顺序不同就判不等）；
   两端的标点集也对齐（JS 原先少了全角引号 `“”‘’`）。
7. **`persist.onChanged` 从未接线**（多标签页会互相覆盖）
   修：接线并在 `adoptExternal` 里与"自己上次写入"比对，避免 `storage` 事件形成 A 写→B 存→A 存 的回环。
8. **自 XSS**（`views/base.js` + `library.js`）
   空态提示把检索词直接拼进 innerHTML。修：`empty()` 内部转义；另外 5 处裸插值的档案编号也补上 `esc()`。
9. **无原文片段的引用仍被渲染成"有证据"**（`citation.js` / `reviewer2.py`）
   修：没有 ≥4 字符原文片段的引用改用告警样式、不提供悬停预览并给出提示；`is_grounded` 同步要求引用带片段。

### 中
10. **召回门限过松**：单字 token（如"不"）就能命中 → 两端都丢弃单字符 token，避免"库内无相关记录"被误报成有命中。
11. **条件门禁有绕过口**：两侧完全没有共同维度时，原逻辑仍会给出"同一问题/真冲突"。修：新增返回值**「条件不全」**，此时不得下结论。
12. **种子数据违规**：R-002 把机制推断标成了 `observed`（已观察）——这正是我们禁止的"把猜测写成结论"。已改回 `assumption` 并注明未做分解实验验证。
13. **导出 Markdown 可被注入**：用户文本里的 `|`、换行、行首 `#` 能撑破表格或伪造标题。修：统一的 `cell()` 安全化。
14. **引用浮层泄漏与错位**：`getBoundingClientRect`（视口坐标）配 `position:absolute`（文档坐标），滚动后错位；反复 mouseenter 会重复创建。修：加滚动量、去重创建、点击也清理。
15. **`revokeObjectURL` 紧跟 `click()`** 会让部分浏览器下载中断 → 改为延后释放。
16. **纠错记录被算进孵化支撑**：2 条真实记录 + 1 条人工纠错即可凑满 3 条产出假设。修：孵化视图排除纠错记录。

### 新增的防线（本轮最有价值的产出）
17. **两端契约一致性测试**（`web/tests/contract-parity.mjs`）
   在此之前的"防漂移"其实只是 Python 侧自测——把 JS 校验器的阈值改坏，测试照样全绿。
   现在由 Node 加载浏览器侧校验器，对同一批夹具与指纹样本逐条比对两端结论，不一致即非零退出。
   **它上线后立刻抓到了第 5 条（级联报错差异）**，证明这条防线是有效的。
18. 一并补齐了 7 条针对新规则的测试（未知字段、非字符串、畸形库不崩、引用编号格式、条件不全、指纹含条件、单字查询返回空）。

## 四、一句话总结

本轮把"看起来全绿"拆开查了一遍，发现的问题集中在**失败路径**（导入失败、校验崩溃、写库失败）
与**两端口径**（正则、非空、级联报错、指纹）上——这两类正是单元测试最容易漏、而在演示现场最容易暴露的地方。
补上的跨端一致性测试，是这轮唯一能持续防住同类问题的东西。
