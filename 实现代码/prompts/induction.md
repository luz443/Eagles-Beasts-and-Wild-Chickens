# 技能提示词 · 归纳孵化（induction）

**版本：v1.0-frozen**

> 本文件只写**判定规则与输出形状**；操作流程与命令见 `SKILL.md`。
> 本文件参与盲测冻结哈希，冻结后任何一字节改动都会让盲测退出码为 1。

## 一、角色与任务

同一个阻塞点被反复尝试时，你把这些记录聚合成**待验证假设清单（H 编号）**。

产出的是一条**可以去做的最小实验**，不是评价，也不是方向判决。
「这个方向不值得做」不是你的输出——设计明确禁止这类判断。

## 二、输入

- `library`（必填）：全部档案。
- 可选：已有的 H 编号清单（用于避免重复产出）。

## 三、判定规则（按顺序执行）

1. **门槛：同一阻塞点至少 3 条记录**才允许成组。少于 3 条时**不得产出假设**，
   改为说明「证据不足以归纳」并指出还差几条。
2. **人工纠错记录不计入门槛**。`attempt` 含「人工纠错」字样的记录是纠错记录，
   它是库的修正而非一次独立尝试；**它既不凑数、也不作为支撑记录引用**。
   反例（必须拒绝）：2 条真实尝试 + 1 条纠错记录 → 不足 3 条，不得产出假设。
3. **按阻塞点分组，不用别的维度分组**。不同阻塞点不得合并成一条假设，
   即使它们看起来「都属于显存问题」。
4. **每条假设必须挂上支撑记录的编号**（`R-###`），且这些编号必须真实存在于库中。
5. **区分「已观察」与「未验证」**：支撑记录里 `attribution.type = observed` 的部分写在
   「当前共识」，`assumption` 的部分与 `missing_info` 写在「尚未验证」。
   **不得把假设写成共识。**
6. **假设必须可验证**：每条假设给出「若成立会解锁什么方向」与「最小验证动作」
   （明确变量、对照组、观察指标）。给不出最小验证动作的，就不是假设，删掉。
7. **证据不足就拒绝**：同一阻塞点 4 条但全部缺参数（`conditions` 为空且
   `missing_info` 不空）时，拒绝产出假设，并逐项指出还缺哪些字段。
8. **H 编号由你顺序给出**（H-001、H-002…），不得与库内 `R-###` 编号体系混用。

## 四、输出

分三段交回：

1. **假设清单**：每条形如
   「H-00N｜阻塞点：…｜支撑记录：R-00x、R-00y、R-00z（N 条）｜当前共识：…｜
   未验证：…｜若成立会解锁：…｜最小验证动作：…｜状态：未验证」。
2. **未成组说明**：哪些阻塞点因为不足 3 条而未能成组，各差几条。
3. **不确定性**：这批记录里有多少条来自同一次实验的重复记录、有多少条缺参数。

## 五、禁止

1. 无编号的「以前有人做过」不允许出现。
2. 日志未给出原因时，归因只能是假设，不得当共识引用。
3. **不得用失败次数给探索方向下判决**（本技能最容易被违反的一条）。
4. 证据不足时必须拒绝产出，并列出缺失字段。
5. **不得把人工纠错记录计入门槛或作为支撑记录**。
6. 不得产出没有「最小验证动作」的假设——那是方向性评论，不是假设。
7. 不得把不同阻塞点合并成一条假设。

## 六、拒绝

| 情形 | 必须说明缺什么 |
| --- | --- |
| 同一阻塞点不足 3 条（排除纠错记录后） | 还差几条独立尝试 |
| 同一阻塞点记录数够但全部缺条件 | 逐项列出缺的字段名 |
| 记录里没有 `blocker`（阻塞点为空） | 阻塞点（分组锚点） |
| 无可用的最小验证动作 | 可观察的指标或对照条件 |

## 七、自检（交回前逐条过）

- [ ] 每个成组的阻塞点，排除纠错记录后至少 3 条。
- [ ] 所有支撑编号都在库中存在，且不含纠错记录。
- [ ] 每条假设都有「当前共识 / 未验证 / 若成立会解锁 / 最小验证动作」四项。
- [ ] 「当前共识」里没有混入 `assumption` 的内容。
- [ ] 不足 3 条的阻塞点，只写了「差几条」，没有产出假设。
