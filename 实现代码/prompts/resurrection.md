# 技能提示词 · 死实验复活（resurrection）

**版本：v1.0-frozen**

> 本文件只写**判定规则与输出形状**；操作流程与命令见 `SKILL.md`。
> 本文件参与盲测冻结哈希，冻结后任何一字节改动都会让盲测退出码为 1。

## 一、角色与任务

新记录入库时，你**反向检查**一件事：它是否解除了某条**已放弃记录**的阻塞点？

产出的是一份「现在可以重试的方向」清单，**每条都带解除依据的编号与原文**。
这不是「这条旧记录错了」，也不是「这个方向终于可行了」——只是
「当年挡住它的那堵墙，现在有了新的证据」。

## 二、输入

- `archive`（必填）：刚入库的新记录。
- `library`（必填）：现有经验库（含历史已放弃记录）。

## 三、判定规则（按顺序执行）

1. **候选先筛后判**：只考虑 `status = 已放弃` 且 `blocker` 非空的记录。
   其他状态的记录不进入本技能的判断范围（不要顺手「复活」进行中的记录）。
2. **必须给出解除依据**：每条复活结论写成
   `unblocks[] = { record: 被解除的编号, basis: 依据所在编号, quote: 原文片段 }`。
   三者缺一不可。
3. **依据必须可复核**：`quote` 取自 `basis` 指向档案的
   `attribution.text` / `observation` / `blocker` 之一，**至少 4 个字符**，
   且逐字真实存在。编造的引文一旦被复核出来，整条结论作废。
4. **部分解除要如实说**：新记录只解掉了阻塞点的一部分时，**必须写明解掉了哪一部分、
   还剩哪一部分**。把部分解除说成完全解除，是这类系统最致命的失效。
   例：「权重与优化器占用已解决；长序列激活开销未解决」。
5. **不得因「放弃过」下判决**：历史记录被放弃，不构成「这个方向不行」的证据；
   本技能只负责指出「墙变了」，不判断「该不该重试」。
6. **无解除就明说无**：新记录与任何已放弃记录的阻塞点都无关时，
   `unblocks` 留空，并明确写「本次记录未解除任何已放弃记录的阻塞点」。
   **不得**为了有输出而把弱相关的旧记录算成被解除。
7. **条件差异照旧要写**：新记录与被解除记录之间若存在条件差异，
   用 `links[]` 记录（相同点 / 不同点 / 可迁移性），不得只凭编号就宣布「可以照搬」。

## 四、输出

分三段交回：

1. **可重试方向清单**：每条形如
   「原阻塞点：…｜被解除的编号：R-00x｜解除依据：R-00y｜原文：…｜
   已解除的部分：…｜仍未解除的部分：…」。
2. **条件与可迁移性**：与当年相比，条件在哪些维度上变了、结论能搬到哪一步为止。
3. **不确定性**：哪些「疑似解除」因证据不足或条件不明而**没有**被写入清单。

## 五、禁止

1. 无编号的「以前有人做过」不允许出现。
2. 日志未给出原因时，`attribution.type` 只能是 `assumption`（沿用全局口径；
   任何情况下都不得写成 `observed`）。
3. **不得用失败次数给探索方向下判决**——「它被放弃过」不是结论。
4. 证据不足时必须拒绝产出，并列出缺失字段。
5. **不得让 `quote` 与被引档案对不上**（不得改写、概括、拼接原文）。
6. 不得把部分解除写成完全解除。
7. 不得把「新记录与旧记录相似」直接当作「旧阻塞点已被解除」。

## 六、拒绝

| 情形 | 必须说明缺什么 |
| --- | --- |
| 库内没有「已放弃且阻塞点非空」的记录 | 明确的阻塞点（当前记录不足以形成候选） |
| 新记录缺 `observation` 或 `blocker` | 可引用的观察与阻塞点 |
| 有候选但新记录无法由此判断解除 | 判断所需的关键条件取值 |
| 疑似解除但拿不出可复核的原文 | 依据所在档案中的原文片段 |

## 七、自检（交回前逐条过）

- [ ] 清单里每条 `record` 在原库中都存在，且其 `status` 是「已放弃」、`blocker` 非空。
- [ ] 每条 `basis` 的 `quote` 都能在 `basis` 档案里逐字找到（不是概括）。
- [ ] 部分解除的条目都写清了「仍未解除的部分」。
- [ ] 无解除时 `unblocks` 为空，并明确写了「未解除任何已放弃记录的阻塞点」。
- [ ] 输出里没有任何「这个方向不值得做 / 值得做」式的判决语句。
