# 研究复盘工作台改造设计

## 目标

让网页真正呈现“证据、条件、复盘、再验证”的研究工作流，并保证前端矩阵与专家侧条件比较使用同一份结构化数据。

## 方案

档案新增可选的 `conditions` 对象，九个维度与 Python 条件比较技能保持一致。历史档案没有结构化条件时，网页显示“未提供”，不从自然语言强行推断。矩阵读取 `conditions`，关系字段只补充专家给出的 same/diff 与迁移说明。

经验库增加概览指标；立项检查直接展示边界、缺失信息和证据摘要；失败地图按阻塞点样本量排序并将成功经验独立归类；孵化清单增加本地验证状态与动作；详情页展示证据链和人工反驳链。所有新增交互保持确定性、本地持久化和现有暖纸朱砂视觉语言。

## 验收标准

1. R-001/R-002 对比时至少显示结构化序列长度、批大小、硬件或精度差异。
2. 立项检查结果可在结果卡内看到边界、缺失信息和证据入口。
3. 失败地图不把“无阻塞点”的成功经验混入失败节点。
4. 孵化假设可标记验证状态，并在刷新后保留。
5. 现有 Python、JS、契约和网页检查全部通过；窄屏无横向溢出。
6. 页面通过公共静态链接可访问。
