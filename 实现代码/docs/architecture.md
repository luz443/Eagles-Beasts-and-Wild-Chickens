# 架构说明（AI 应用架构师视角）

> 对应设计方案 v1.3：第三章（系统架构）、第五章（功能设计）、第七章（验证方案）、第十章（风险）。

## 一、技术路线

三层，单向依赖，无环：

```
契约层  contracts/（JSON Schema + 维度枚举 + 纯函数校验）
   ↑                       ↑
Python 侧 src/rra/     网页侧 web/
（技能脚本、库、召回、评测、种子、导出）  （只读视图 + 本地持久化）
```

| 层 | 职责 | 是否使用模型 |
| --- | --- | --- |
| 契约层 | 定义档案、关联、证据引用的形状与取值域；提供确定性校验 | 否 |
| Python 侧 | 技能脚本（供 LearnBuddy 技能调用）、库读写与合并、召回打分、用例评测、种子数据、导出 | 否（AI 判断由平台侧的专家完成） |
| 网页侧 | 八类视图 + 引用上标 + 反驳入口 + 导入导出 + 本地持久化 | 否 |

数据流（六步最小闭环）：新记录 → 专家抽取与反查 → 人工确认 → 导出结构化文件 → 网页导入并持久化 → 再次检索命中。

### 1.1 `skills/*.py` 的 `build()` 做的是把关，不是推理

平台实测确认：**技能脚本无法调用模型**（唯一涉网脚本走的是平台云服务能力，需连接器授权，赛规亦禁用）。
因此语义判断由专家本身承担，技能代码只做确定性把关。
`build()` 的输入是专家已经交回的产出（`SkillInput.context["expert_output"]`），它做四件事：
**取专家 JSON → 规则门禁 → 规范化 → 违规抛 `ValueError` / 证据不足抛 `SkillRefusal`**。
本层不联网、不导入任何模型 SDK —— 这是「网页侧零模型调用」之外的第二条硬边界。
`base.py` 的 `build()` 保持抽象（`NotImplementedError`）是刻意的：默认实现会让「忘了写门禁」静默通过。

### 1.2 两个常被误读的口径

- **`conditions` 与 `links[].same/diff` 不是同一样东西**：前者是档案**自己的**实验条件（门禁的输入），
  后者是专家**已作出的判定结果**（结论）。所以条件对比矩阵读 `links`、条件门禁读 `conditions` 是刻意分工，
  不是同源缺陷。详见 `docs/record-format.md`。
- **规则若只在 schema 里管不到，就必须在两端各放一个测试**：曾经的「人工纠错记录不计入归纳门槛」
  只在网页端实现，导致同一个库两端结论不同。现在这类**行为约定**（纠错过滤、可重试候选、拒绝产出）
  都由「规则唯一真源 + 两端各一个测试」守着（`tests/test_refutation_filter.py` /
  `tests/test_resurrection_filter.py` 与 `web/tests/*-rule-parity.mjs`）。

## 二、选型对比

### 2.1 实现语言与运行时

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **Python 3.11+（标准库为主）** | 与平台技能脚本同语言；本机隔离环境已就绪；纯函数易测 | 前端无法复用 | **采用**（工具链与确定性逻辑） |
| Node / TypeScript 全栈 | 前后端同语言 | 需要依赖安装与构建；本机 Bash 不可用、离线风险高 | 不采用 |
| 不写代码，全部留在平台提示词里 | 零开发量 | 工程完整性 25% 要求代码质量与架构设计，无法满足 | 仅作降级预案（见 5.2） |

### 2.2 前端形态

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **原生 ES Module，零构建** | 直接静态托管；无 node_modules；评委可读源码 | 无类型检查、无打包优化 | **采用** |
| Vite + TypeScript | 类型安全、生态成熟 | 引入构建产物与依赖声明，7 天内增加交付风险 | 备选（团队若已熟悉可替换） |
| React / Vue 框架 | 组件化 | 体积与学习成本；静态托管仍是必需 | 不采用（YAGNI） |

### 2.3 持久化

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **库文件导入 + localStorage** | 无后端；刷新与重开仍在；可导出后可复现 | 本机单浏览器，换设备不同步（已如实声明） | **采用**（设计方案 §3.3 方案 A） |
| IndexedDB | 容量大、可存二进制 | 复杂度上升，对 15–25 条档案无收益 | 不做 |
| 后端 / 云函数 | 真正多人共享 | 与「低成本、不加后端」及剩余工期冲突 | 不做 |

### 2.4 契约校验

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **JSON Schema + 手写纯函数校验** | 无第三方依赖；前后端可共享同一份 schema；可单测 | 需要自己写校验逻辑 | **采用**（用例 25 就是它） |
| pydantic | 表达力强、错误信息好 | 引入第三方依赖（需在 THIRD_PARTY_NOTICES 注明），前端无法复用 | 备选 |
| 只靠文档约定 | 零成本 | 无法满足「契约一致性」用例，返工风险高 | 不做 |

### 2.5 AI 能力承载

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **LearnBuddy 专家 + 技能脚本** | 符合赛事唯一平台要求；确定性部分留在本地可测 | 需要人工导入文件（如实展示） | **采用** |
| 网页内直接调用模型 | 体验连贯 | 平台未开放对外通路，且禁止第三方 AI | 不做 |

### 2.6 召回实现

| 选项 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **确定性打分（字段加权 + 关键词）** | 可解释、可测、可输出命中解释 | 召回率有上限 | **采用**（网页侧只做召回，判定交给专家） |
| 向量检索 | 语义召回更好 | 需要嵌入模型（第三方），且无法解释 | 不做 |
| 不做召回，全部靠人工翻列表 | 零成本 | 立项检查不成立 | 不做 |

## 三、评测口径

指标体系（越靠上越重要）：

| 指标 | 定义 | 采集方式 | 目标 |
| --- | --- | --- | --- |
| 引用正确率 | 输出中的 `evidence_refs` 能对回真实档案编号与原文片段的比例 | 人工核对 + 校验脚本 | 100%（出现无出处引用即失败） |
| 越界归因率 | 把「假设」写成「结论」、或给出无证据归因的比例 | 校验脚本（`attribution.type` 必须是枚举值）在无证据时必须为 `assumption` | 0 |
| 契约合法率 | 专家输出通过 schema 校验的条目占比 | `rra.contracts.validator` | 100% |
| 命中率 | 提示「库里有人做过」时，实际存在相关档案的比例；反之为漏报 | 用例集逐条判定 | 见用例判据 |
| 闭环可用性 | 新档案导入后能被同一阻塞点检索命中 | 用例 18–20 | 必须通过 |

盲测协议（不可违反）：

1. 10 条盲测用例在提示词冻结前**不得打开**。
2. 冻结时记录提示词版本号与时间。
3. 冻结后一次性跑完，过程不得调参。
4. 改进后必须做反向测试，确认真冲突仍能被识别（防止矫枉过正）。

## 四、成本估算

模型：`Credits 消耗 = 专家调用次数 × 单次成本`。**单次成本当前未知**，是唯一的未知量。

| 用途 | 次数上限 |
| --- | --- |
| D1 成本探测 | 3 |
| 开放用例（15 条分批） | 15 |
| 盲测（10 条一次性） | 10 |
| 演示录屏 | 1 |
| 真实迭代留痕（含一次返工复测） | 6 |
| **合计** | **35** |

预算 2500 Credits / 队。判定规则：若 D1 测出单次成本 > 60，则开放用例压缩到 6 条（走降级预案），
优先保盲测 10 条与录屏 1 次。本地确定性部分（召回、校验、导出、种子数据）零 Credits。

## 五、风险与降级

### 5.1 技术风险

| 风险 | 触发条件 | 影响 | 应对 |
| --- | --- | --- | --- |
| 平台技能不支持放代码 | 平台实测确认只支持提示词 | 确定性校验与召回无法随技能下发 | 走 5.2 降级 1 |
| 契约字段被自由文本污染 | 专家把 `dim` 写成自然语言 | 对比矩阵与高亮失效 | 校验器直接拒绝 + 用例 25 守住 |
| 编号冲突 | 两人各自导入 | 档案互相覆盖 | `dedup_key` + 重编号 + `remap_from` |
| 本地存储被清空 | 用户清浏览器数据 | 演示中断 | 演示前导出库文件作为兜底 |

### 5.2 降级预案（与设计方案 §10.2 一致）

1. 技能不能放代码 → 把比对维度与输出模板全部写进提示词，用固定样本回归。
2. 连接器不通 → 保留手动导入（本就是采用的方案）。
3. 只剩两天做网页 → 保「库 + 检索 + 立项检查 + 导入导出」，砍矩阵与孵化清单视图。
4. 用例跑不完 → 只跑盲测 10 条 + 闭环回归 3 条。
5. 种子数据来不及 → 先用 1–2 条真实记录做完整闭环样例。
