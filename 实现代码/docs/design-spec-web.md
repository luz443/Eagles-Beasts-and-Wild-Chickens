# 网页视觉规格与设计令牌（design-spec-web）

> 适用范围：`实现代码/web/`。本文档是网页视觉的**唯一真源**：改任何颜色、字号、间距，先改这里的令牌，再让组件层引用。
> 配套代码：`web/css/tokens.css`（令牌）→ `web/css/base.css`（基础层）→ `web/css/components.css`（组件层）。
> 实测证据：对比度结论见 `reports/design-contrast-2026-09-19.txt`；逐视图截图见本文档末尾「验证记录」。

## 一、定调说明（Direction Lock）

**目的**：给「研究复盘助手 · 经验库」一个与其内容本质同构的界面 —— 它管理的是**带编号、带证据、可复核的研究档案**，不是一个通用后台。

**受众**：科研团队（研究者 / 导师 / 学生）与比赛评委。评委在 3 分钟内要能看懂"记录 → 召回 → 复核"的闭环。

**调性（只选一个）**：**杂志编辑 / 学术档案刊（Editorial Archive）**。规则线、多栏索引、宋体大标题、等宽编号、纸感底色 —— 期刊与档案库的视觉语言。不混搭任何科技感渐变或圆角卡片风。

**记忆点（评委离开后记得的东西）**：
1. 朱砂色"档案印"体系 —— 页顶一道 3px 朱砂压顶线 + 品牌印记 + 强调色统一；
2. 每条档案是一张**索引卡**：左侧状态色带 + 等宽编号 + 宋体标题；
3. 引用上标 `[R-008]` 点开即见原文片段，无片段的引用带 `?` 明示"不可复核"。

**明确不做的事**：暗色主题（纸感是核心记忆点，暗色会抹平它）；CDN 网络字体（比赛演示与录屏环境可能无外网，加载失败即翻车）；彩色渐变背景；图标库（本产品无装饰性图标需求，用排版与色带表意）。

### 2.2 字体

| 令牌 | 栈 | 角色 |
| --- | --- | --- |
| `--font-display` | `Georgia, "Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", "SimSun", serif` | 标题、页签、表头（拉丁走 Georgia，中文自然回落宋体系） |
| `--font-body` | `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Source Han Sans SC", sans-serif` | 正文 |
| `--font-mono` | `"Cascadia Mono", "JetBrains Mono", Consolas, "Courier New", monospace` | 档案编号、得分、日期、统计数字 |

**为什么本地字体栈、不上 CDN 字体**：交付环境包含比赛现场与录屏，外网不可依赖；`font-display: swap` 解决的是"加载慢"，解决不了"加载失败"。Georgia + 宋体是主动选择的印刷感配对，不是默认值（禁用清单针对的是把 Inter/system-ui 当展示字的无思考用法）。

**对基准值的两个有意偏离**（都写在这里，不藏在代码里）：
- 展示字大小：应用型界面（非落地页），首屏标题取 `clamp(28px, 3.4vw, 38px)`，不追 48px+；
- CJK 大标题**不做负字距**：负值会让汉字互相挤压，`--ls-display` 取 `0.01em`。

### 2.3 字阶 / 行高

| 令牌 | 值 |
| --- | --- |
| `--fs-xs / sm / base / md / lg / xl` | 12 / 13 / 16 / 18 / 21 / 26 px |
| `--fs-2xl` | `clamp(28px, 3.4vw, 38px)` |
| `--lh-tight / snug / base` | 1.15 / 1.4 / **1.75**（中文正文 ≥ 1.7） |
| 正文行长 | `--measure: 68ch`（中文约 34 字，落在 28–40 字区间） |

数字一律 `font-variant-numeric: tabular-nums`（编号、得分、日期、统计），列不跳动。

### 2.4 间距 / 圆角 / 阴影 / 层级

- 间距：`--sp-1…9` = 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 px，组件只允许取刻度值；
- 圆角：`--r-xs 2px / --r-sm 3px / --r-md 4px`（印刷品是方的，只做轻微倒角；胶囊形只留给统计点）；
- 阴影三级：`--sh-1`（Y2）/ `--sh-2`（Y8）/ `--sh-3`（Y24），带暖调环境色 `rgba(26,23,20,…)` 而非纯黑；
- 层级固定刻度：`--z-atmos 0 / --z-base 1 / --z-sticky 10 / --z-popup 50 / --z-toast 60`，禁止临时数字。

### 2.5 动效

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--dur-fast` | 160ms | 交互反馈（≤ 200ms 铁律） |
| `--dur-base` | 320ms | 入场、常规过渡 |
| `--dur-slow` | 640ms | 弹层 |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 统一缓动 |
| `--stagger` | 60ms | 入场错峰间隔 |

**只动 `transform` 与 `opacity`**，不动画任何布局属性。所有动效包在 `prefers-reduced-motion: reduce` 的全局降级之下（base.css）。

## 三、组件标注规范

> 标注格式：组件 → 结构 → 关键规格 → 状态覆盖。

### 3.1 顶栏（`.topbar`）
- 结构：3px 朱砂压顶线（`border-top`）→ 品牌行（印记 34×34 + h1 + 统计徽标）→ 副标语 → 操作按钮 → 页签行。
- 品牌印记 `.brand-mark`：朱砂底 + 白字"研"，`--r-xs` 倒角；与页顶压顶线构成"档案印"记忆点。
- 统计徽标 `.badge.stat`：等宽数字 + 6px 朱砂圆点；**红点只出现在顶栏**，正文统计徽标不带点（防止强调色泛滥）。
- 状态：载入中（"正在载入…"）→ 数据态（"15 条档案 · 模拟 15"），变化经 `role="status"` 播报。

### 3.2 页签（`.tabs`）
- 结构：`nav > button`，CSS 计数器自动生成序号 `01–05`（等宽小字，`aria-hidden` 语义由文本承载）。
- 规格：下边一条 `--rule` 发丝线贯通；激活项 = `aria-current="page"` + 字重 600 + 2px 朱砂下划线。
- 为什么用 `aria-current` 而不是 `aria-selected`：本页签是**导航**而非 tablist（tablist 模式要求每个 tab 配独立 panel，本应用是单容器替换内容）。半套 ARIA 比不用更糟。
- 状态：默认（`--ink-2`）→ 悬停（下划线 `scaleX(0→1)` 扫过）→ 激活 → 键盘聚焦（2px 焦点圈）。

### 3.3 按钮
| 变体 | 用途 | 规格 |
| --- | --- | --- |
| 默认 | 次级动作 | 白底 + `--control` 描边，悬停 `--paper-2` |
| `.primary` | **每屏唯一**的关键动作 | 朱砂底白字（6.46:1），悬停 `--accent-strong` |
| `.warn` | 破坏性/质疑动作（反驳） | `--danger` 描边与文字 |
| `.ghost` | 第三层动作（取消、关闭） | 透明底 |

- 最小高度 40px（桌面）/ 44px（`pointer: coarse`）；按下 `translateY(1px)`；过渡 160ms。

### 3.4 档案卡（`.card--record`）—— 全站核心组件
- 结构：`article[data-status]` → 左侧 4px 状态色带（`.rec-rail`）+ 内容区（`.rec-body`）。
- 内容区：序号（等宽 `01`）→ 编号徽标（`.badge.id`）→ 标题（宋体 `.rec-title` 内嵌 `.rec-open` 真按钮）→ 阻塞点 → 归因行（归因徽标 + 文本）→ 元信息徽标行。
- **键盘可达方案**：整卡可点（鼠标），但键盘焦点落在卡内唯一的真按钮 `.rec-open` 上 —— 不用 `tabindex=0 + role=button` 复刻按钮行为（那是手工重建键盘行为，易错）。
- 色带颜色由 `data-status` 驱动：进行中 `--warn` / 已放弃 `--danger` / 已绕过 `--ok` / 已解决 `--done`。
- 状态：默认 → 悬停（`translateY(-1px)` + `--sh-2` + 标题下划线扫过）→ 焦点可见 → 空态另见 3.8。

### 3.5 徽标（`.badge`）
- 通用：12px、`--r-xs`、纸灰底。
- 归因徽标：`已观察`（绿底实线）/ `归因假设`（赭底**虚线**）—— 文案 + 底色 + 线型三重区分，色盲与黑白打印都不误读。这是"假设不得写成结论"这条产品铁律的视觉执行。
- 状态徽标：`.st-进行中/已放弃/已绕过/已解决`，底色 + 文字双承载。

### 3.6 表格（`.matrix-table`）
- 外层必须有 `.table-scroll`（`overflow-x: auto`）—— 小屏横向滚动发生在容器内，**页面**不出现横向滚动（探针实测 390px 视口 `scrollWidth == 390`）。
- 键列 `.th-key`：`--paper-2` 底 + `nowrap`（「提出人 / 时间」不许折行）。
- 差异行 `tr.diff`：暖赭底 + 行首 3px 朱砂竖标 —— 不只靠底色表意。

### 3.7 引用上标（`.citation`）
- 规格：等宽、`vertical-align: super`、朱砂点线下划线；悬停/聚焦反白底 `--accent-wash`。
- **无原文片段**的引用：`.citation-bad` 追加 `?` 并改用 `--danger` 实线 —— "不可复核"必须一眼可见，这是证据规则的视觉化。
- 浮层 `.citation-popup`：墨底纸字（16.70:1）、`--sh-3`、160ms 淡入；悬停**与键盘聚焦**都触发（纯悬停是可访问性缺陷）。

### 3.8 空态 / 轻提示
- 空态：标题 + 说明 + **一个明确的下一步动作**（导入库文件，`.js-import` 事件委托接住）。只说"空"等于把问题丢回给用户。
- 轻提示 `.toast`：替代 `alert()` —— 不打断操作流、可承载导入明细、`aria-live` 播报、超 3 条挤掉最旧、可手动关闭。错误类提示停留 10s。

### 3.9 工具栏（`.card--toolbar` → `.toolbar`）
- 结构：`flex` 横排、`gap: var(--sp-3)`（12px，满足相邻触控目标 ≥8px 间距）；三项一组：检索（`.field-wide`，占满剩余宽度）→ 状态下拉 → 排序下拉。
- **每个控件都有可见标签**（`.field-label`），不用 placeholder 充当标签。
- 排序下拉 `#lib-sort`：库内顺序 / 置信度低在前 / 被关联多在前。**顺序即语义**——默认项排第一，也是 URL 里被省略的那一项（见第十节）。
- 命中摘要 `.hits-summary`（`role="status" aria-live="polite"`）：无筛选报"共 N 条档案"；有筛选报"命中 M 条，共 N 条档案"；**非默认排序追加** `· 按「置信度低在前」`——用户改了排序，界面必须回话。
- 控件选择器必须覆盖全部输入类型：曾漏掉 `input[type="search"]`，检索框一直吃浏览器默认样式，与旁边的下拉框边框、高度、底色都对不上（已由 CDP 实测修正，见 10.3）。
- 状态：默认 → 悬停 → 聚焦（2px 朱砂圈）→ 无命中（列表位显示空态，工具条保留以便就地改条件）。

### 3.10 快捷键提示（`.kbd-hint` + `kbd`）
- 位置：页签行下方；`--fs-xs` + `--ink-3`（仍达 4.5:1 以上），不参与交互、不进焦点顺序。
- 键帽 `kbd`：等宽字体 + `--paper-2` 底 + `--rule-strong` 描边 + 2px 下边——读起来像"一个键"而不是"一段代码"。
- 为什么写在界面上：**快捷键不可发现等于不存在**；它同时是"键盘可用"的可见承诺，与 3.2 的焦点可见策略同源。

## 五、响应式意图

| 断点 | 决策 |
| --- | --- |
| ≥1440 | 内容 1100px 居中，两侧留白展示纸面与颗粒 |
| ~768 | 工具条换行；页签换行成两排；卡片保持单列 |
| 375 | 页签纵向堆叠；表格进入容器内横滚；**页面无横向滚动**（实测 320 / 390px 均 `scrollWidth == innerWidth`） |

> 触控目标口径：Web 端适用 WCAG 2.2「Target Size (Minimum) ≥ 24×24 CSS px」，**不是** iOS 的 44pt / Android 的 48dp——那是原生平台规范，套到 Web 上会得出错误结论。本项目控件最小高度 40px、按钮在 `pointer: coarse` 下 44px，均高于 Web 底线。

## 九、如何改版

1. 换肤：只改 `tokens.css` 的令牌（例如换强调色 = 改 `--accent / --accent-strong / --accent-wash` 三个值），组件层不动；
2. 新组件：先查本文档有没有同类，有则复用类名；没有则先在本文档补标注再写 CSS；
3. 加新颜色前必须先过对比度实测（`_build/contrast_check.py` 模式可复用），并把结果登记进 `reports/design-contrast-*.txt`。

## 十、路由与键盘交互规范（2026-09-19 晚追加；2026-09-20 同步「可重试方向」）

### 10.1 路由格式（`web/js/route.js`，纯函数，不碰 DOM 与 history）

| 状态 | URL | 说明 |
| --- | --- | --- |
| 经验库（默认） | `#/library` | 默认状态不写参数，链接最短 |
| 经验库 + 条件 | `#/library?q=…&status=…&sort=…` | 只记"与默认不同"的项；`sort=order` 被折叠掉 |
| 其余六个视图 | `#/projectCheck`、`#/map`、`#/compareMatrix`、`#/incubation`、`#/resurrection` | 与页签一一对应 |
| 可重试方向 + 阻塞点 | `#/resurrection?blocker=长序列训练显存不足` | 只看该阻塞点的已放弃记录；选中项**默认展开** |
| 立项检查 + 检索词 | `#/projectCheck?q=长序列训练显存` | **别名是 `q` 不是 `query`**：`routeToHash` 把 `query` 写成 `q`，`parseHash` 也只认 `q`；写 `?query=` 会被当成未知参数静默忽略（不报错，但检索不会跑）。已在浏览器实测中实测到过 |
| 档案详情 | `#/detail/R-003` | 深链到单条档案 |

- **导航用 push，状态用 replace**：切视图 / 开档案写新历史记录（返回键可退）；同一视图内改检索词、筛选、排序只**替换**当前记录——否则每敲一个字都塞一条历史，返回键要按十几次才退得出去。
- **坏链接不动作**：认不出的 hash（`#/nope`、`#/detail` 缺编号）返回"不处理"，既不白屏也不改写地址栏。
- **降级**：`file://` 等来源为 opaque 的环境里 history API 可能抛 `SecurityError`，降级为直接改 `location.hash`。两条路径都有实测（10.3）。
- 测试：`web/tests/route-roundtrip.mjs`（**23 项**，往返 / 默认值折叠 / 坏链 / 转义）；
  `web/tests/workbench.mjs` 另含 5 条跨视图深链上下文保留断言（含 `resurrection`）。

### 10.2 键盘交互（`main.js` → `bindShortcuts`）

| 键 | 行为 | 边界 |
| --- | --- | --- |
| `1`–`6` | 切到第 1–6 个页签视图 | 焦点在 input/textarea/select/contenteditable 内**不生效**（否则打字按到 1 就整页跳走）；超出页签数量的数字键不拦截 |
| `/` | 回到经验库并聚焦检索框 | 已在经验库时**就地聚焦**、不重挂载（否则已输入的检索词会丢） |
| `Tab` | 顺序与视觉顺序一致，首站为 `.skip-link` | 实测：第一个 Tab 落在"跳到主要内容" |
| `Esc` | 关闭引用浮层 | 与既有行为一致（`citation.js`） |
| `Enter` | 立项检查提交 / 引用上标跳转 | 与既有行为一致 |

> 为什么是 1–6：可切换的**页签**有 6 个（经验库 / 立项检查 / 失败地图 / 条件对比矩阵 / 孵化清单 / **可重试方向**）。
> 档案详情不是页签（由卡片或深链进入），所以**不给它数字键**——造一个没有对应入口的快捷键是假的可用性。
> 实现上不写死数量：`bindShortcuts` 按页签列表长度匹配 `/^[1-9]$/`，超出数量的数字键不拦截，交给浏览器。

### 10.4 排序规则（`web/js/util/sort.js`，纯函数）

- `order` 库内顺序（默认）→ `confidence` 置信度低在前（越不确定越需要人先复核，贴合"复核优先"的产品语义）→ `linked` 被关联多在前。
- **显式稳定排序**：同值按原索引兜底，不依赖引擎的排序稳定性；返回新数组、不改入参。
- 非法 / 缺失模式静默回落 `order`——URL 是用户可手改的，不能因此白屏或抛错。
- 测试：`web/tests/sort-order.mjs`（10 项，含稳定性与非破坏性）。
