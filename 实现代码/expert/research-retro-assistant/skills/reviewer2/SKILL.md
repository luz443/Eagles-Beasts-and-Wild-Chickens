# 技能 6：第二复核者（reviewer2）

## 用途

对**已有结论**做一次带证据的质疑：这条判断的依据够不够？边界写得对不对？有没有被忽略的反例？
和技能 3（条件对比）的区别：技能 3 比两条记录，本技能质疑**一条结论本身**。

## 什么时候用

- 用户说「这条结论靠谱吗」「帮我挑毛病」「复核一下」；
- 归纳/立项前做一道质量闸（避免把一个弱结论当立项依据）。

## 输入

一条档案（或一条假设），可选：全库（用于找反例）。

## 步骤

1. **逐项过清单**（每一问都要给出结论，不能跳过）：
   - **依据是否可核**：`attribution.type` 是 `observed` 还是 `assumption`？若是 `observed`，
     原文里那句话是否真的支持该结论？
   - **引用是否成立**：`evidence_refs` 的片段是否真的存在于被引用记录里（用 `recall` 或直接比对）；
   - **边界是否够窄**：`boundary` 写了哪些条件？有没有把只在特定条件下成立的结论写成普遍结论？
   - **反例**：库里是否存在条件相似但结论相反的记录（先跑 `condition-compare`）。
2. **给出质疑等级**：
   - `成立`：依据可核、边界清楚、无已知反例；
   - `存疑`：依据是假设，或缺边界，或存在未被解释的反例；
   - `不成立`：引用不存在 / 引用不支持结论 / 与已核实的观察矛盾。
3. **每条质疑必须带证据**：指出档案编号 + 原文片段 + 问题所在；不允许「感觉不太对」。
4. **给出最小修补建议**：补哪个维度值、补哪条引用，就能把等级提上去。

## 输出

- 复核结论：等级 + 逐条质疑 + 修补建议。
- 中文说明：这条结论现在能用到什么程度（能否作为立项依据）。

## 拒绝条件（必须照做）

- **不允许无证据质疑**：说不出具体依据的怀疑，写「不确定，暂不评价」而不是列为问题。
- 不得直接改写被复核的档案：质疑通过 `links`（`relation: 冲突`）与新增纠错档案表达，
  原判断保留（撤回不删除）。
- 复核自己刚写的结论时同样按本清单走一遍，不能自我豁免。
