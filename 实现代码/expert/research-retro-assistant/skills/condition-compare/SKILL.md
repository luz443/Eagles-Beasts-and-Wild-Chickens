# 技能 3：条件对比（condition-compare）

## 用途

两条记录结论不一样时，判断它们**是不是真的冲突**——先对齐条件，再谈结论。
（一条在 24G 单卡上失败、另一条在 8 卡上成功，这不是矛盾，是条件不同。）

## 什么时候用

反查时发现两条记录结论相反；用户问「这两条为什么结论不同」「算不算冲突」。

## 输入

两条档案 JSON（`<a>`、`<b>`）。

## 步骤

1. **先跑确定性对比**（差异维度与结论都由代码算，别自己目测）：

```bash
python3 bin/rra_cli.py condition-compare <a.json> <b.json>
```

   返回：
   - `differing_dims`：条件里不同的维度（来自九维枚举）；
   - `verdict`：`同因` / `异因` / `条件不全`。

2. **解释 `verdict`**（语义，你来做）：用一句话说清「因为哪个维度不同，所以结论不同」。
3. **条件不全时不许下结论**：`verdict == "条件不全"` 意味着两侧没有共同的可比维度，
   此时结论只能是「条件不全，不能判定冲突」，并在 `missing_info` 里列出需要补齐的维度值。
4. **写入 `links`**：把这次判定落到档案的 `links[]`（`relation` 取 `冲突` / `相似`），
   `diff` 里写具体维度差异。

## 输出

- 对比结论（`differing_dims` + `verdict` + 你的中文解释）。
- 建议的 `links` 更新内容。

## 拒绝条件（必须照做）

- 不要用「实验结果不同」这种话充当差异——差异必须落在**维度**上（模型 / 序列长度 / batch /
  精度 / 硬件 / 数据集版本 / 阶段 / 框架 / 微 batch）。
- 两侧没有共同维度时**禁止**给出「谁对谁错」；只能说条件不全。
- 不要修改两条档案的原始 `observation`，冲突靠 `links` 表达，不靠改写历史。
