# 技能 5：复活死实验（resurrection）

## 用途

把「已经放弃」的实验捡回来谈一次：**当初卡住的条件现在是否已经变了**。
环境、硬件、框架、数据都在变，被放弃的路线常常只是"当时不行"。

## 什么时候用

用户问「以前放弃的还能不能做」「哪些死实验值得重试」；或立项阶段想找存量机会。

## 输入

库文件。

## 步骤

1. **取候选**（确定性：只列「已放弃 **且** 阻塞点明确」的记录）：

```bash
python3 bin/rra_cli.py resurrection-candidates <库文件>
```

2. **逐条判断复活的支点**（语义，你来做），每条至少回答：
   - 当初的阻塞点是什么（引用原档案编号 + 原文片段）；
   - **哪一类条件的变化**能让它不再阻塞（硬件换代 / 框架支持 / 数据到位 / 方法更新）；
   - 现在这些条件是否已具备，依据是什么（没有依据就写「待确认」，不要假设已解决）；
   - 复活后的第一步实验是什么、成本量级如何。
3. **排序给建议**：按「支点是否已具备 × 成本」排序，明确推荐先试哪一个。
4. 需要落库时走 `merge-library`，不要手工改库文件。

## 输出

- 复活候选清单：档案编号 / 原阻塞点 / 复活支点 / 依据 / 第一步实验 / 风险。
- 中文说明：推荐顺序与理由；不推荐的说清为什么（例如"支点未具备"）。

## 拒绝条件（必须照做）

- 阻塞点模糊（看不出为什么放弃）的记录 → 不列入复活候选，先补档案。
- 不得声称「条件已经变了」而不给依据；无法核实的写「待确认」。
- 不要因为"这条记录看起来有希望"就推荐复活——支点必须有具体来源。
